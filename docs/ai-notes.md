# AI notes

This project is built with Claude Code. This file records where the agent
was wrong or unsure, what caught it and what changed. It is kept as the
work goes, not written at the end.

## How the agent is kept in check

- **A contract first.** The design note, then the spec and the test plan,
  are written and confirmed before the code they describe.
- **One gate.** `npm run check` runs formatting, types, lint and unit tests.
  A git pre-commit hook runs it, so a failing change cannot be committed by
  a person or by an agent.
- **A stop hook.** In a Claude Code session opened in this repository,
  Claude is sent back to work when it tries to end a turn with uncommitted
  changes while the checks fail (`.claude/hooks/stop-check.sh`).
- **Rules written down.** `AGENTS.md` holds the rules of the codebase and
  what "done" means.
- **Tests that can fail.** Each rule is broken once on purpose to see a
  check go red (`/break-a-rule`). The results are in the second table.
- **A second reader.** A read-only subagent reviews a change against the
  spec (`.claude/agents/spec-reviewer.md`).
- **The owner confirms every step** before the next one starts.

What has not been exercised is listed at the end.

### The HTTP layer and the database

The same procedure, against a real PostgreSQL, running the HTTP tests
for the file each rule lives in.

| The rule                                                    | The edit                                                   | The tests that failed                                                                                      |
| ----------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| A result cannot arrive before 60 seconds                    | The too-early check in `RoundsService` switched off        | "rejects a result before 60 seconds, then accepts it at 60"                                                |
| A round accepts one result                                  | `completed_at is null` removed from the UPDATE             | "lets exactly one of two simultaneous completions succeed", "refuses to complete a round twice"            |
| Only the hash of the key is stored                          | The key stored instead of its hash                         | "stores only the hash of the key", and the key no longer found the player                                  |
| Protected routes need a key                                 | The global guard removed                                   | 17 tests: every 401 case and `GET /api/me`                                                                 |
| Protected routes need a key                                 | `@Public()` put on `RoundsController`                      | The eight 401 cases for the two round routes                                                               |
| A round is looked up for its own player                     | The player id removed from `findForPlayer`                 | "answers Ben's result for Ada's round as if the round did not exist"                                       |
| Progress is read for its own player                         | The player id removed from the progress query              | "shows a player none of another player's rounds"                                                           |
| Abandoned rounds are left out of progress                   | `completed_at is not null` removed from the progress query | "leaves out a round that was issued and never completed"                                                   |
| A result that loses the race is reported as 409             | `if (!stored) throw` removed from `RoundsService`          | "reports a result that lost the race to another as already completed" (a unit test with a fake repository) |
| The pace before a round leaves that round out               | The filter by round id removed                             | "works out the usual pace before this round from the other rounds, wherever this one sorts"                |
| The scores behind a result's pace are this player's         | The player id removed from that query                      | "leaves out another player's scores"                                                                       |
| The scores behind a result's pace are completed rounds only | `completed_at is not null` removed from that query         | "leaves out a round that was never completed"                                                              |

With `completed_at is null` removed from the UPDATE, the HTTP test for a
second result still passed: the service checks for an existing result
first, which stops two results that arrive one after the other. Only the
tests on the query itself caught the gap that two results arriving
together would leave. That is why the test plan tests that query
directly.

## Not exercised yet

- The Stop hook has not fired inside a live Claude Code session opened in
  this repository. The build session was opened in the parent folder, and
  a nested repository's `.claude/settings.json` is not documented to load
  there. The hook script was run by hand with the JSON a Stop event sends.
- The permission rules in `.claude/settings.json` have not been exercised,
  for the same reason.

The `/check` skill and this repository's `CLAUDE.md` did load in the build
session, because Claude Code picks those up from a nested folder when it
works on files there.

The `/break-a-rule` skill was used for the first domain rule. Subagent
definitions in a nested repository are not loaded, so the `spec-reviewer`
instructions were given to a general-purpose subagent limited to reading
files. It reviewed `src/domain` and found the gaps in row 11.
